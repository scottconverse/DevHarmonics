## Open blocking findings — MUST fix before any release

### B-1 (Blocker) — cmd.exe command injection via quote-parity break
`scripts/path-resolve.mjs`, `escapeCmdArg`. An argument containing an **odd
number of `"` characters** followed by a shell metacharacter escapes its
quoted context; `&` and `|` become live cmd.exe syntax. Proven: a second,
attacker-chosen process launched from what should have been one opaque `-p
<prompt>` argument, through the real `runWorker` → `buildInvocation` →
`superviseProcess` path. Reachable whenever adversarial text lands in a
`claude`/`agy` argv-delivered prompt on Windows. Impact: arbitrary command
execution as the operator, entirely outside the worktree sandbox.

### B-2 (Blocker) — symlink escape in `local-patch.mjs`, read *and* write
`assertRelativeRepoPath` validates path *strings* only; it never resolves the
real filesystem target. A git-committed symlink (mode `120000`) with an
absolute target is followed transparently. Read side: outside file content
lands in the model's prompt. Write side, worse: the model's content
overwrites the outside target **while the receipt reports "model returned
unchanged content (empty diff)"** — git tracks the symlink object, not the
resolved target, so `git diff --cached` never sees it. A real out-of-repo
write reported as nothing happening is precisely the false-negative this
product exists to prevent.

### C-1 (Critical) — embedded newlines silently truncate the command line
Any argument containing `\r`/`\n` causes cmd.exe to drop everything after the
first line once ComSpec-wrapped. Proven against the real reviewer prompt
(multi-line by construction): `--output-format json`, `--model`,
`--max-turns`, `--permission-mode`, `--allowedTools`, `--add-dir` were **all
silently dropped**. It happened to fail closed in testing, but the truncation
point is content-dependent and unchecked — that outcome is incidental, not
guaranteed.

### C-2 (Critical) — the validator runs with the full, unstripped environment
`workerEnv()` is correctly wired for the worker and the ACP adapter, but not
for the `--check` command in either lane (`run-command.mjs`,
`local-patch.mjs`). The check executes **inside the worktree the untrusted
worker just committed to**, so one planted line in a test file or a `pretest`
hook executes with every credential on the box. Proven: a fake secret
appeared in `stdoutTail`, then propagated into the pipeline's `--json` output
*and* into the reviewer's prompt via `checkReceiptsSummary`. This defeats
SPEC §2.5 for the most natural workflow the tool has.

- **M-1** — `claimsArtifactDivergence` is structurally inert in production:
  `run-command.mjs` computes `claimedPaths` from `git diff --name-only`, never
  from the worker's narration, so the gate compares the diff to itself. Proven:
  a worker falsely claiming an auth fix while touching an unrelated file
  reached READY with 0 divergence. The gate is sound; nothing feeds it.
- **M-2** — F-1's identity check verifies only that `--version` *looks like* a
  semver. A deliberate stub printing `9.9.9` passes. Real defense against
  accidental substitution, not against the named threat actor. The repo-side

  `DBPASSWORD`, `SESSIONTOKEN`, `STRIPESECRETKEY`, `DB_PASS`, `MYSQL_PWD`,
  `PRIVATE_KEY`, `DATABASE_URL`, `REDIS_URL`, `SENTRY_DSN`.
- **M-4** — `worker-command.mjs` and the Windows bare-executable edge were
  uncovered; a fix was in flight at report time.
- **Minor/unproven** — NTFS Alternate Data Stream paths (`app.js:hidden`) pass
  validation; not confirmed exploitable.

## Honest note on how this gate was run

The repository was under live development *during* the audit; three roles
independently detected HEAD moving beneath them and re-pinned their findings
to specific commits. That is a real methodology weakness — a gate should run
against a frozen ref. The tests role froze its own clone and did all mutation
work there; the others re-verified against the current HEAD before reporting.
Findings that were already fixed mid-audit are marked as such above rather
than double-counted.
